# Неделя 1, День 4 — массивы и слайсы

**Время:** 60 минут
**Цель:** понять, что слайс — это не список, а окно в массив, и перестать удивляться поведению `append`.

Самая коварная тема первой недели. Слайсы выглядят как привычные массивы из JavaScript и ведут себя иначе. Вопрос «что внутри слайса» задают на собеседованиях чаще любого другого.

---

## 0–10 мин. Чтение

- [ ] [Go Slices: usage and internals](https://go.dev/blog/slices-intro) — официальная статья, читать целиком

Модель, которую нужно унести:

- **Массив** — фиксированная длина, **значимый тип**. При присваивании копируется целиком. `[3]int` и `[4]int` — разные типы
- **Слайс** — структура из трёх полей: указатель на массив, `len`, `cap`. Сам слайс передаётся по значению, но **массив под ним общий**
- `len` — сколько элементов доступно. `cap` — сколько помещается без переаллокации
- `append` при `len < cap` пишет **в существующий массив**. При `len == cap` выделяет новый и копирует
- Поэтому результат `append` обязательно присваивается обратно: `s = append(s, x)`

### Задача 1. Эксперименты (≈20 мин)

Файл `<ваше-имя>/week01/day04/slices/main.go`. Четыре опыта, каждый — **сначала предсказание, потом запуск**.

**А. Как растёт ёмкость.**

```go
var s []int
prev := -1
for i := 0; i < 20; i++ {
	s = append(s, i)
	if cap(s) != prev {
		fmt.Printf("len=%2d cap=%2d\n", len(s), cap(s))
		prev = cap(s)
	}
}
```

Обратите внимание: `var s []int` — это `nil`-слайс, но `append` к нему работает. Проверьте `s == nil` до первого `append`.

**Б. Общий массив.**

```go
a := []int{1, 2, 3, 4, 5}
b := a[1:3]
b[0] = 99
fmt.Println(a, b)
```

Что стало с `a`? Почему?

**В. Главная ловушка.**

```go
a := []int{1, 2, 3, 4, 5}
b := a[1:3]
fmt.Println(len(b), cap(b))   // сначала посмотрите на cap

b = append(b, 777)
fmt.Println(a, b)
```

`append` не выделил новый массив — места хватило. И затёр чужой элемент. Найдите, какой именно.

**Г. Два способа защититься.**

```go
// Способ 1: полная копия
a := []int{1, 2, 3, 4, 5}
b := make([]int, 2)
copy(b, a[1:3])
b = append(b, 777)
fmt.Println(a, b)   // a цел

// Способ 2: трёхиндексный срез — обрезаем cap
c := []int{1, 2, 3, 4, 5}
d := c[1:3:3]
fmt.Println(len(d), cap(d))
d = append(d, 777)
fmt.Println(c, d)   // c цел
```

**Проверка:** можете объяснить словами, почему в «Г» массив `a` уцелел, а в «В» нет.

## Частые грабли четвёртого дня

**`append(s, x)` без присваивания.** Компилируется, ничего не делает. Всегда `s = append(s, x)`.

**`make([]int, 5)` там, где нужен `make([]int, 0, 5)`.** Первый вариант создаёт срез из пяти нулей, и первый же `append` добавит шестой элемент. Симптом: в результате пять лишних нулей в начале.

**Изменение элемента в `range`.** `for _, v := range s { v = 0 }` не меняет ничего: `v` — копия. Нужно `for i := range s { s[i] = 0 }`.

**Сравнение слайсов через `==`.** Ошибка компиляции. Сравнивать можно только с `nil`. Для поэлементного сравнения — `slices.Equal` из стандартной библиотеки.

**`nil`-слайс против пустого.** `var s []int` даёт `nil`, `s := []int{}` — не `nil`. Оба имеют `len` 0 и оба работают с `append`. Разница станет важна на пятой неделе: в JSON первый сериализуется в `null`, второй в `[]`, и фронтенд это заметит.

**Удержание большого массива маленьким срезом.** Если из среза на миллион элементов взять `s[:10]` и сохранить надолго, весь миллион останется в памяти — сборщик мусора не может освободить массив, на который есть ссылка. Лечится явной копией через `copy` или `slices.Clone`.
