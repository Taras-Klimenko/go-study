## 10–50 мин. Работа

### Шаг 1. Установка Go

- [ ] **macOS:** `brew install go`, либо `.pkg` с [go.dev/dl](https://go.dev/dl) — brew иногда отстаёт на релиз
- [ ] **Linux:** распаковать tarball с go.dev/dl в `/usr/local/go`, добавить `/usr/local/go/bin` в `PATH`
- [ ] **Windows:** `.msi` с go.dev/dl

**Проверка:**

```bash
go version
```

Должно вывести `go1.27.x`. Если версия ниже — разберитесь с `PATH` сейчас, не откладывая.

### Шаг 2. Редактор

- [ ] Установить расширение **Go** от Google (`golang.go`)
- [ ] `Cmd/Ctrl+Shift+P` → `Go: Install/Update Tools` → выбрать всё

Ставятся `gopls` (языковой сервер), `dlv` (отладчик), `staticcheck` (линтер).

- [ ] Добавить в `settings.json`:

```json
{
  "[go]": {
    "editor.formatOnSave": true,
    "editor.defaultFormatter": "golang.go"
  }
}
```

**Проверка:** открыть любой `.go`-файл, намеренно сломать отступы, сохранить. Форматирование должно выправиться само.


### Шаг 3. Первая программа

- [ ] Создать `<ваше-имя>/week01/day01/main.go`:

```go
package main

import (
	"fmt"
	"runtime"
)

func main() {
	fmt.Println("Привет, Go!")
	fmt.Printf("Версия: %s, ядер: %d\n", runtime.Version(), runtime.NumCPU())
}
```

**Проверка:**

```bash
go run ./<ваше-имя>/week01/day01
```

Должны увидеть приветствие, версию и число ядер.

### Шаг 4. Четыре команды

Не просто запустить, а посмотреть, как каждая ведёт себя на сломанном коде.

- [ ] **`gofmt`** — форматирование

```bash
gofmt -l .        # показывает файлы с неканоничным форматированием
gofmt -w .        # исправляет
```

Сломайте отступы намеренно, убедитесь, что файл появился в выводе `-l`, затем исправьте.

- [ ] **`go vet`** — ловит то, что пропускает компилятор

```bash
go vet ./...
```

Впишите заведомо неверное `fmt.Printf("%d\n", "строка")`, запустите `vet`, прочитайте ошибку, уберите строку.

- [ ] **`go build`** — сборка бинарника

```bash
go build -o bin/hello ./<ваше-имя>/week01/day01
./bin/hello
```

Получился один самодостаточный исполняемый файл без рантайма и внешних зависимостей. Это ровно то, за что Go любят при деплое.

- [ ] **`go run` против `go build`** — понять разницу: первый компилирует во временную директорию и сразу запускает, второй оставляет артефакт на диске.

**Проверка:** `go vet ./...` молчит, `gofmt -l .` не выводит ни одного файла.

## Частые грабли первого дня

**`go version` работает, а `gopls` в редакторе не подхватывается.** Почти всегда `~/go/bin` не прописан в `PATH` — именно туда `go install` кладёт инструменты.

**Попытка положить проект в `$GOPATH/src`.** Наследие до-модульной эпохи. С модулями репозиторий может лежать где угодно.

**`go run main.go` вместо `go run ./путь/к/папке`.** Работает, но привыкайте к варианту с пакетом — дальше в проектах будет несколько файлов в одном пакете, и первый вариант перестанет собираться.
