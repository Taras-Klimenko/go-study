# Неделя 1, Суббота

**Время:** 80–90 минут вдвоём в созвоне
**Цель:** закрыть непонятое за неделю, посмотреть код друг друга, поработать в паре.


---

## До созвона — 10 минут, каждый отдельно

- [ ] Прогнать `gofmt -l .` и `go vet ./...`
- [ ] Убедиться, что весь код за неделю запушен
- [ ] Открыть папку напарника на GitHub и бегло пролистать — чтобы на созвоне не тратить время на первое знакомство с кодом

---

## Часть 1. Разбор непонятого — 15 минут

Правило: **сначала объясняет тот, кто разобрался**, и только если не получилось у обоих — идёте в документацию или к нейросети. Объяснение вслух — это и есть проверка, что вы правда поняли, а не узнали.

Типичные темы этой недели, если своих вопросов не набралось:

- Почему `append` иногда меняет чужой слайс, а иногда нет
- Чем `var s []int` отличается от `s := []int{}`
- Почему `len("Привет")` равен 12
- Что именно происходит при `defer track("x")()` и зачем вторые скобки
- Почему неиспользуемая переменная — ошибка компиляции, а не предупреждение

- [ ] Всё, что не смогли объяснить друг другу, завести как issue в `go-study` с меткой `question`

---

## Часть 2. Взаимное ревью — 25 минут


### Чеклист на код первой недели

Про идиоматичность:

- [ ] Ошибка проверяется сразу после вызова, а не через несколько строк
- [ ] Нигде нет `_ = err` без комментария, зачем ошибка проигнорирована
- [ ] `fizzBuzz` возвращает строку, а не печатает внутри себя
- [ ] Текст ошибки называет конкретику: позицию, значение — а не «неверный формат»
- [ ] В `Filter` есть преаллокация через `make([]int, 0, len(nums))`
- [ ] `Map` и `Filter` не мутируют входной срез
- [ ] В частотном словаре при равных частотах есть сортировка по алфавиту

Про стиль:

- [ ] Именование: `userID`, а не `userId`; сокращения в верхнем регистре целиком
- [ ] Имена переменных короткие там, где область видимости мала (`i`, `s`, `err`), и говорящие там, где велика
- [ ] У экспортируемых функций есть доккомментарий, начинающийся с имени функции
- [ ] Нет закомментированного кода и отладочных `fmt.Println`

Про то, чего быть не должно:

- [ ] Ни одного `panic` в обычной логике
- [ ] Никакой зависимости от порядка обхода мапы
- [ ] Нет конкатенации строк в цикле через `+=`

### Формат замечаний

Замечания оформляются как issue в `go-study` с меткой `review` и ссылкой на строку кода — на GitHub ссылку на строку даёт клавиша `y` и клик по номеру. Устные замечания забываются к понедельнику.

## Часть 3. Парное программирование — 30 минут

Две задачи с [Exercism Go track](https://exercism.org/tracks/go). Обе подобраны под материал недели.

### Как работать

Схема «драйвер — навигатор»:

- **Драйвер** пишет код и не принимает решений в одиночку
- **Навигатор** думает на шаг вперёд, задаёт вопросы, не диктует буквы
- **Смена каждые 15 минут по таймеру.** Ровно по таймеру, даже на середине функции

Экран шарит драйвер. Пишете в репозитории того, кто сейчас за клавиатурой.

### Задача 1: Reverse String (≈15 мин)

Развернуть строку. Кажется тривиальным, пока в тестах не появляется кириллица и эмодзи — прямое продолжение вчерашнего дня про руны.

- [ ] Наивная версия через байты — посмотреть, как она ломается на `"Привет"`
- [ ] Правильная версия через `[]rune`
- [ ] Прогнать тесты: `go test`

### Задача 2: Hamming (≈15 мин)

Расстояние Хэмминга между двумя строками ДНК. Сигнатура — `func Distance(a, b string) (int, error)`, ошибка при разной длине строк. Материал третьего дня в чистом виде.

- [ ] Продумать до кода: какие есть краевые случаи и что возвращать в каждом
- [ ] Реализовать
- [ ] Прогнать тесты

Если успеете обе за 25 минут — берите третью на свой выбор. `Isogram` или `Acronym` хорошо ложатся на материал недели.

## Если что-то пошло не так


**Спор о том, как правильно.** Не решайте голосованием и не спорьте дольше трёх минут. Заводите issue с меткой `question`, смотрите [Go Code Review Comments](https://go.dev/wiki/CodeReviewComments) или [Google Go Style Guide](https://google.github.io/styleguide/go/) — в 90% случаев ответ там уже есть.
